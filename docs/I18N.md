# Traductions français / anglais

L’application utilise `lang/fr.php` et `lang/en.php`, sans framework, extension
intl ou dépendance supplémentaire. Le français est la langue par défaut.
`app/I18n/Translator.php` charge uniquement ces deux catalogues autorisés.

Le sélecteur FR | EN commun (`app/Views/language-switch.php`) est présent sur la
connexion, dans l’en-tête et sur les erreurs publiques. Il effectue un POST
`/language`, protégé par CSRF. La langue est conservée dans `$_SESSION['language']`,
y compris lors du renouvellement de session, de la connexion, de la déconnexion
et de l’expiration de l’identité. Changer de langue ne détruit pas l’identité,
les rôles ou le jeton CSRF. Aucun accès MySQL n’est nécessaire pour cette action.

Le cookie de session existant conserve le choix entre les requêtes ; aucun cookie
de préférence supplémentaire n’est nécessaire. Il garde les attributs HttpOnly,
SameSite=Lax et Secure sous HTTPS. Après une session entièrement perdue, le français
redevient la langue par défaut. La langue du navigateur ne remplace pas ce défaut.

Le retour après changement de langue est limité aux routes locales autorisées,
avec conservation des paramètres de recherche/pagination. Une URL extérieure ou
invalide retourne vers le tableau de bord. Une langue différente de fr/en est
refusée en 422. GET /language est refusé en 405.

## Convention pour toutes les prochaines fonctionnalités

Tout nouveau texte destiné à l’utilisateur doit avoir une clé identique dans les
deux catalogues : titre, menu, légende accessible, champ, placeholder, bouton,
validation, erreur et notification. Ne pas écrire les libellés directement dans
les vues, contrôleurs ou JavaScript. Les noms propres et données métier saisis
par les utilisateurs ne sont pas traduits.

```php
// Texte simple : toujours échapper lors de l’insertion dans du HTML.
echo h(t('modules.contracts'));

// Paramètres nommés ; l’échappement intervient après leur interpolation.
echo h(t('dashboard.greeting', ['name' => $user['first_name']]));

// Stocker une clé, puis traduire au moment de l’affichage de la notification.
$_SESSION['flash'] = 'notifications.employee_updated';
```

Les catalogues sont du texte brut, sans HTML. Ne pas y injecter du balisage ; les
symboles et la structure restent dans la vue. Les libellés utilisés par JavaScript
proviennent d’attributs data-* traduits côté PHP ; les afficher avec textContent.
Les validations de champs obligatoires sont aussi transmises au JavaScript depuis
les catalogues, avec validation serveur toujours présente.

Les espaces de clés existants comprennent `login.*`, `nav.*`, `roles.*`,
`employees.*`, `employee.*`, `employee_form.*`, `validation.*`, `notifications.*`,
`errors.*` et `dashboard.*`. Les libellés `modules.employees`, `modules.contracts`,
`modules.payroll`, `modules.finance`, `modules.administration` et `modules.audit`
sont déjà disponibles pour les prochaines interfaces. Ajouter leurs textes métier
dans les deux catalogues lors du développement effectif de chaque module.

Les codes persistés en base (`hr_manager`, etc.) et la matrice RBAC ne changent pas.
Leur affichage utilise `roles.<code>`, jamais le libellé anglais stocké en base.
Une traduction anglaise absente retombe sur le français ; une clé absente des
deux catalogues affiche un message générique centralisé, sans détails internes.
Les paramètres de traduction doivent être identiques dans les deux langues.

## Vérifications réalisées

- Parité des 162 clés et des paramètres FR/EN.
- Dix rendus de vues existantes (cinq en français, cinq en anglais), avec contrôle
  du lang HTML, de l’échappement et de l’absence de traduction manquante.
- Validations serveur traduites et retours de langue locaux filtrés.
- HTTP : français par défaut, sélection EN persistante dans la même session,
  connexion et erreurs anglaises, CSRF obligatoire, langue invalide refusée,
  redirection externe bloquée, conservation EN après déconnexion puis retour FR.
- Cycle de session CLI isolé : préférence conservée à la connexion et à la
  déconnexion ; identité et CSRF conservés lors du changement de langue.
- Syntaxe valide des 22 fichiers PHP dans app/, config/, public/ et lang/.

Ces vérifications ne se substituent pas à une authentification avec un vrai
compte MySQL. Le module PDO, les requêtes d’authentification et le dépôt des employés
ne sont pas modifiés par cette mission. Les prérequis MySQL restent ceux de
WEB-SETUP.md ; aucune migration, écriture MySQL ou commande Git n’a été effectuée.

L’interface locale reste accessible sur http://127.0.0.1:8080/login.
